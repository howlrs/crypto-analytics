# 判断の原則: 利益の源泉、裁定、値付け、取引所、検証

暗号資産と株の実践者が公開している記事（約 260 本）を 2026-11 に精読して抜き出した原則を、このリポジトリで使う形にまとめたもの。
記事の本文や数値は載せない。ここにあるのは著者たちの経験則で、この環境で検証した事実ではない。
この環境で確かめたことは [台帳](operating-loop.md)（`research_loop/`）に書く。売買推奨ではない。

読む視座は一貫して「何を観測し、どのパラメータに落とし、仮説と検証をどう回したか」である。測定の伴わない主張は、参考にとどめて数字を使わない。

## 1. 利益は誰かの不利な取引から出る

戦略より先に、払っている相手を言う。言えないものは採用しない（`hypotheses.json` の `payer`）。

| 源泉 | 払っている人 | 観測できる痕跡 | 寿命 | このリポジトリの仮説 |
|---|---|---|---|---|
| レバレッジの借り賃 | 無期限先物のロングを持ち続ける人 | funding、先物と現物の差 | 構造的。水準は過熱で大きく変わる | H-001、H-002、H-013 |
| 強制される売買 | 清算される人、指数に連動する資金、制度で売買を迫られる人 | 清算の溜まり、建玉、日程 | 仕組みが続く限り。参加者が増えると薄まる | H-003、H-008 |
| 急ぎの成行 | 価格を確かめずに売買する人、急変時に投げる人 | 大きな成行の連続、取引所間の価格差 | 熱狂と事故の間だけ厚い | — |
| 補助金と設計の穴 | 取引所やプロトコル、報酬目当てに不利な取引をする人 | 料率表、告知、仕様 | 告知や規則の変更で終わる | — |
| 古い価格の指値 | 更新の遅い値付け、価格を自分で動かせない流動性の提供者 | 市場間の先行と遅行、板への反映の遅れ | 速い順に取られる | H-010（棄却） |
| 未整備の市場 | 最初に来た人以外 | 出来高の小さい取引所や銘柄 | 数日〜数週間 | — |

活況と閑散で、同じ仕組みの収益は桁が変わる。成績の良い期間だけで期待値を決めない。

## 2. 新しい仮説を受け付けるときの問い

`hypotheses.json` に行を足す前に答える。答えられない項目は、そのまま「未特定」「不明」と書く。

1. **誰が払っているか。なぜ払い続けるか。**
2. **価格差や歪みが残っている理由は何か。** 誰も見ていない、見られない、収束の手段（送金、出金、借入）が止まっている、売買を強制されている、のどれか。
3. **いつ、何で終わるか。** 競合が来る、規則が変わる、機会を取り切る。依存している規則と、止める条件を書く。
4. **自分が実際に売買できる最初の価格から測っているか。** 発表や信号の時点ではなく、約定できる時点から。
5. **必要なパラメータは台帳にあるか。** `unknown` なら、検証より先に測る。
6. **1 回の期待収益と、往復コストの期待値を同じ単位（幅）で比べたか。** 時間軸はそれに合っているか。
7. **1 回の最大損失を決められるか。** 決められないものは運用に出さない。
8. **検証で何を仮定したか。** 約定、遅延、試した回数、期間の分け方。前向きの観察に進む条件は何か。

## 3. 価格差を取る

- 探すのは価格差そのものではなく、収束を妨げているもの。妨げが消えれば差も消える。
- 必要な価格差を先に数える。手数料、為替やヘッジの費用、執行の間の値動きを足す。資金力のある参加者はもっと小さい差で動くので、平時に個人が取れる差はほとんど残らない。
- 稼げるのは熱狂と事故の局面に偏る。そのとき出金や送金が詰まる。資金を事前に置き、迂回路を把握していた人だけが動ける。
- 原理上の損失がない形から始める。取るリスクを、取引相手と決済手段に限る。
- 寿命は短い。手動で取れる → 自動化される → 閾値を食い合う → 撤退、が数日から数か月で進む。終わり方を先に想定する。
- 先物と現物の差は、熱狂時に開き続けて売り側が耐えられなくなることがある。過熱の度合いを読めないなら、価格差より借り賃を受け取る形が無難。
- 最大のリスクは取引相手。相場が低調な時期ほど、取引所や仕組みの破綻が起きる。

## 4. 指値を出す

- 指値は「逆に動いてから戻る」ことへの賭けを必ず含む。戻らなければ負ける。勝負は幅ではなく、約定した後の値動きで決まる。
- 設計は、置き場所、在庫の戻し方、止めどきの 3 つ。在庫の管理は、現在のポジションを正確に取れることが前提で、取得が遅れる環境では成り立たない。
- 同じ値段は先着順。後ろに並ぶと、自分の番が来るのは価格が突き抜けるときだけになる。
- 成行は同じ向きに固まって来る。両側が均等に約定する前提を置かない。
- 手数料の戻りは損を減らすが、約定後の不利な値動きを上回るとは限らない。
- 成り立つのは、速さで列の先頭を取れる、値付けの競争がない、指値に報酬が付く、雑な成行が多い、のいずれかがある場。
- **予測できることと取れることは別。** 短い時間軸は予測しやすいが、1 回の収益が小さく回数が多いので、コストと遅延で消える。
  長い時間軸（数時間以上）は執行より予測が課題になり、成行でも影響が小さい。

## 5. 取引所はパラメータの束

同じ銘柄でも、取引所で結果が変わる。次を定数として持ち、変更を監視する（`parameters.json` の group と対応）。

| 項目 | group |
|---|---|
| 手数料（指値・成行、報酬の有無）、実際の往復コスト | `cost` |
| funding の式、上限、間隔。急変時に間隔が短くなる条件 | `funding` |
| 担保の掛目、維持証拠金率、口座の種類ごとの条件 | `margin` |
| 清算の判定単位（銘柄ごとか口座全体か）、清算価格が見えるか | `liquidation` |
| 受信の遅延とそのばらつき、注文が板に反映されるまでの時間 | `latency` |
| 名目額別の成行コスト、板の厚さ、約定後の値動き、市場間の先行と遅行 | `liquidity` |
| 足や時刻の規約、観測の母集団、取得の間隔 | `data` |

- 規則が収益機会を作り、同じ規則の変更で終わる。規則に依存する仮説は、その規則を `kill` に書く。
- 担保の掛目、料率、funding の上限は、予告なく変わる。`documented` の値は日付で古くなる。
- 急変時は、平時に同じだった価格が取引所ごとに離れる。清算の判定単位が違えば、同じポジションでも結果が違う。
- 注文回数の上限、短時間の大量の発注と取消への照会、口座の凍結は、収益より先に運用を止める。

## 6. 大衆の心理より、強制される売買と機械的な売買

- 再現しやすいのは、心理の読みではなく、制度や証拠金で売買を迫られる参加者と、決まった日程で機械的に売買する資金を特定すること。
- 広く知られた指標（建玉の偏り、funding、時刻の傾向）は、検証すると弱いか、コストで消えるか、知られた後に劣化していることが多い。
  単独の売買規則にせず、絞り込みや他の材料との組み合わせとして扱う。
- 時刻の傾向は、条件を変えやすく理由を後付けしやすいので、過剰適合しやすい。本当に効くのは決まった時刻に機械的に売買する主体がいる場合だが、外からは理由も消滅も分からない。
- 清算は情報と関係のない売買なので戻りやすい、という見方には、有効な局面と、大きな下落で利益を失う局面の両方がある。
- 個人の優位は、大きな資金が入れない場所と、資金が小さいことにある。同じ理由で、自分も出られないことがある。

## 7. 検証の落とし穴

結果を良く見せるもの:

- 約定の仮定が甘い（価格に触れたら約定、列の順番を数えない）。
- 遅延を入れていない。受信、計算、注文のそれぞれに時間がかかる。
- 自分の注文が他人の行動を変えることを無視している。
- 多くの条件を試して、良かったものを選んでいる。
- 売れない銘柄、値幅制限、板の薄さを無視している。
- 手数料以外のコスト（滑り、自分の注文の影響、約定できなかった機会）は、仮定では正確に入らない。

防ぐ手:

- 実際に動かす環境で遅延を測り、過去データに当ててから検証する。遅延のばらつきも入れる。
- 約定の判定を、厳しめ・列の順番・甘めの 3 通りで並べる。甘めだけ良ければ信用しない。
- 条件を決める期間と確かめる期間を分ける。試した数に応じて補正する（[strategy-robustness.md](strategy-robustness.md)）。
- 前向きの観察を、規則を固定してから行う（[prospective-validation.md](prospective-validation.md)）。
- 有意でない結果は、有意でないと書く。

## 8. 資金管理と止める仕組み

- 期待値がプラスでも、賭け金が大きすぎれば破産する。賭け金は直感より小さくする。
- 平時に適切と感じる水準より、さらにリスクを下げる。急変時には、人は平時と違う行動をとる。
- 複数の戦略が同時に損をする相関が致命傷になる。急変時は相関が上がる。
- 大きな損失の型は共通している。前提の甘さ、同時の被弾、止める仕組みの不在、平時の感覚で決めたレバレッジ。
- 止める条件を先に決め、自動で止める。候補は、入力が検証時の範囲から外れた、損失が上限を超えた、受信が遅れている、取引所が保守や高負荷の状態にある、他の取引所との価格差が異常、など。
- 1 つの仕組みに全資金を入れない。利益の一部は外に出す。

## 9. このリポジトリの判定との照合

原則と、ここで実際に確かめた結果が同じ向きを指しているか。

| 原則 | このリポジトリの結果 | 根拠 |
|---|---|---|
| 借り賃は払う相手を言える | funding の受け取りは検証を通り、払う相手を説明できた（運用は保留） | H-001 |
| 広く知られた指標は弱い | funding・建玉の過熱への逆張り・順張りは優位なし | H-004 |
| 時刻の傾向は先に取られている | funding の決済時刻の前後は、粗利がコストに届かない | H-005 |
| 清算の後の戻りは局面を選ぶ | 単独では不採用。確認基準を通る候補は 0 件で、追跡だけ登録 | H-003 |
| 乗り換えはコストに負ける | 取引所の乗り換えは、1 か所に固定する場合に劣る | H-006 |
| 価格差は、残る理由を言えないと扱えない | 取引所間の差は記述まで。残る理由を特定していない | H-007 |
| 「レバレッジのロングは負ける」を一般論にしない | 日本株の信用買いでは一部しか支持されなかった | H-016 |
| コストは仮定ではなく実測で | 板の 1 か月分を集計した。滑り片道 2bp の仮定は BTC・ETH では保守的、HYPE の 10 万ドル以上では不足。実際の約定でのコストは未計測 | `liquidity.impact_bp`、`cost.event_study.slippage_bp`、`cost.realized_round_trip_bp` |
| 遅延を測ってから短い時間軸を語る | REST の往復時間は実測した（場所で 2〜3 倍違う）。配信の受信遅延、板への反映、約定後の値動きは未計測 | `latency.*`、`liquidity.post_fill_move_bp` |
| 古い価格を取るには速さが要る | BTC の急変の後、ETH・HYPE に 1 分足で見える遅れはなく、追随は往復コストを下回った | H-010 |

食い違いは見つかっていない。ただし、右の列の多くは「棄却した」「測っていない」であり、原則が正しいことの確認ではない。

## 範囲と限界

- 元の記事は、語の一致で機械的に選んだ一部で、成績は著者の自己申告である。時期に依存する記述が多い。
- 記事ごとの抜き出しと出典は、リポジトリの外（手元の知見の記録）にある。記事と図は著者の著作物なので、ここには転載しない。
- 本書は判断の手がかりで、検証の代わりにはならない。
