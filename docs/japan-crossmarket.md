# 日本市場の公開時点データと BTC/ETH の将来リスク

`backtests/japan_crossmarket.py` は、J-Quants の日本市場データが暗号資産の判断に
**無料データ以上の情報を足すか**を、公開時刻に合わせた因果的な設定で調べる探索的分析です。
`backtests/japan_session_reversal.py` は、その過程で見つかった事後パターンを独立期間で一度だけ検証します。
売買推奨ではありません。2026-08-01 UTC の研究境界を越えず、封印済み registry や既存 results は変更しません。

## 結論

1. **日経225オプションの30日 ATM IV（JIV）は、BTC/ETH の翌1日・3日の変動予測に追加情報を持ちません。**
   暗号資産自身の5分足実現ボラティリティ（HAR）と VIX に JIV を加えると、OOS R² は4セルすべてで
   −0.25%〜−1.65%（BH q = 0.86）。全期間の回帰でも JIV の係数は −0.03〜−0.05（HAC t −0.66〜−1.01）です。
   判断時刻を東証の日中取引終了直後（07:00 UTC）に早めた事後感度でも同じでした。
2. VIX も実質的に足しません（OOS R² −0.30%〜+0.18%、q ≥ 0.61）。一方、HAR だけで拡大平均に対する
   OOS R² は 0.50〜0.54 で、4暦年すべて正です。**レバレッジや清算余裕の判断には、株式側の恐怖指数より
   暗号資産自身の直近の実現ボラティリティを使う**のが、この期間のデータに沿った選択です。
3. 日本株ストレス日の後に暗号資産が反発する（日本時間の投げ売りを欧米時間の流動性が吸収する）という
   利益源泉は**再現しませんでした**。発見期間（2021–2026）では欧米時間の戻りが見えましたが、事前に固定した
   条件で2017–2020年に当てると符号が逆でした（BTC 片側 p = 0.77）。戦略候補から外します。
4. ボラティリティ目標（0.5、上限4倍）の重ね合わせは、2023–2026年の BTC で一定1倍より Sharpe が低く
   （0.92 対 1.02）、JIV を加えても変わりません。

この範囲の問いについて、暗号資産側で J-Quants を使い続ける根拠は見つかりませんでした。
取得・構築の仕組み（`data-tools/fetch_jquants.py`）は、別の仮説を検証するときに再利用できます。

## 問い

1. JIV は、暗号資産自身の実現ボラティリティと米国 VIX を知った後でも、BTC/ETH の翌1日・3日の
   実現ボラティリティ予測を改善するか（主仮説）。
2. 日本株の急落・IV急騰日の後、BTC/ETH は反発するか（強制売りの肩代わり）、続落するか（リスクオフの伝播）。
   探索的な副次分析です。

主仮説を予測リスクに置いたのは、プロジェクトの制約（レバレッジ4倍以下、清算余裕、BTC/HYPE の長期保有）に
直接使えるのが将来の変動幅だからです。リターン予測は既存の funding/OI シグナル転用が全滅しており、
同じ形の検定を日本データで繰り返しても事前確率は低いと考えました。

## データと公開時刻

| データ | 出所 | 公開時刻の扱い |
|---|---|---|
| TOPIX 日足 OHLC | J-Quants `/indices/bars/daily/topix`（bulk） | 公式目安 16:30 JST |
| 日経225オプション日足（清算値・IV・建玉） | J-Quants `/derivatives/bars/daily/options/225`（bulk） | 公式目安 27:00 JST（翌日 03:00 JST） |
| 取引カレンダー | J-Quants `/markets/calendar`（bulk） | 欠落日の検査だけに使う |
| VIX 終値 | FRED `VIXCLS` | 米国日付 d−1 の終値（判断時点で確定済み） |
| BTCUSDT/ETHUSDT 1分足 | `market.db` の Binance USDT-M perp | 完了足のみ |

日本の営業日 d ごとに、判断時刻を **T = d 19:00 UTC（d+1 04:00 JST）** に固定します。
オプションの公式更新目安に1時間の余裕を足した時刻で、すべての J-Quants 特徴量がこの時点で公開済みです。
TOPIX は16:30 JST に出ますが、時計を一つにするため同じ T を使います（日本側に有利な仮定はしない）。
日本側の入力も 2026-08-01 より前に切ります。

## 特徴量と目的変数

- 暗号資産: 1分足終値から5分対数リターンを作り、(T−1日, T]、(T−7日, T]、(T−30日, T] の
  年率実現ボラティリティを計算します。5分格子が1本でも欠けた窓は欠測です（補完しない）。
- JIV: 各限月（SQ日で識別）について、SQまで7暦日以上の限月だけを使い、原資産価格に最も近い行使価格で
  プット・コールの清算値と IV がともに正のものを ATM とし、両者の IV の平均を取ります。
  対象となる近い2限月の総分散を暦日で線形に結び、30日の値を取ります。2限月とも30日より先なら外挿します
  （週次限月がなかった頃の VIX が近限月の満期前に次の2限月へ移ったのと同じ扱い）。
  緊急取引証拠金発動時の行（区分 `001`）は使わず、清算価格算出時の行（`002`）だけを使います。
- VIX: 米国日付が d より前で、5暦日以内の最新値。T の時点で米国市場はまだ開いているため当日値は使いません。
- TOPIX: d の終値と、7暦日以内の直前営業日終値との対数リターン。
- 目的変数: (T, T+h] の年率実現ボラティリティ（h = 1, 3 日）、T の分足始値から T+h の分足始値までの
  対数リターン、期間中の最大逆行（安値）と最大順行（高値）。

## 主仮説の検定（事前に固定）

対数ボラティリティを OLS で予測する4モデルを比べます。

| モデル | 説明変数 |
|---|---|
| M0 | log RV(1日), log RV(7日), log RV(30日)（HAR） |
| MV | M0 + log VIX |
| MJ | M0 + log JIV |
| MVJ | M0 + log VIX + log JIV |

- 2023-01-01 以降の各判断時刻で、目的変数の窓が T までに完了した行だけで再推定する拡大窓 OOS です
  （h=3 では T−3日より後の行を学習に使いません）。学習行は250行以上を要求します。
- 入れ子モデルなので Clark–West 検定（片側、Newey–West ラグ 5h）を使います。
- **主ファミリー**: MVJ 対 MV（BTC/ETH × h=1,3 の4セル）。Benjamini–Hochberg で補正します。
- 副ファミリー: MJ 対 M0、MV 対 M0（8セル）。JIV の情報が日本固有か、無料の VIX で足りるかを見ます。
  参考として M0 対「学習済み目的変数の拡大平均」も出します（HAR 自体に予測力があるかの確認）。
- **判定規則**: 主ファミリーのいずれかのセルで q < 0.05、かつ OOS R²（MV 比）が全体で正、
  2023〜2026 の4暦年のうち3年以上で正、2024年8月を除いても正のとき、
  「J-Quants の JIV は暗号資産のリスク予測に頑健な追加情報を持つ」と判定します。それ以外は「頑健な追加情報なし」。
- 年別 OOS R²、月を1つずつ除いた OOS R² の最小値とその月、QLIKE、全期間回帰の係数（HAC t）を併記します。

## 補助の診断（判定には使わない）

- **ボラティリティ目標の重ね合わせ**: BTC/ETH ロングのレバレッジを `min(4, 0.5 / 予測ボラ1日)` とし、
  各 T で調整、7bp（taker 5bp + slippage 2bp）× |Δレバレッジ| のコストを引きます。funding と最後の手仕舞いコストは含めず、
  週末・祝日をまたぐ保有にも1日予測をそのまま使います。M0/MV/MVJ による差を記述します。
- **日本ストレス日のイベント**: TOPIX リターンが d より前の履歴（2016-10 以降、250日以上）で見た5%分位以下の日、
  または Δlog JIV が同様の95%分位以上の日。直前に採用したイベントから h 日未満で前方窓が重なるイベントは間引きます。
  イベント後リターンの平均と全営業日平均の差を月クラスター bootstrap（4,000回）で評価し、
  8セル内で BH 補正します。反発なら正、伝播なら負。片道7bp（taker 5bp + slippage 2bp）控除後の値も出します。

## 結果（集計値のみ）

OOS は 2023-01〜2026-07（h=1 で874点、h=3 で872点）。データ検査: TOPIX の欠落営業日0、
自前の JIV と JPX の基準ボラティリティ（7日以上の最近限月）の相関 0.983。

| セル | MVJ 対 MV の OOS R² | CW p | BH q | 正の年 | 2024-08 除外 |
|---|---:|---:|---:|---:|---:|
| BTC 1日 | −0.60% | 0.68 | 0.86 | 0/4 | −0.43% |
| BTC 3日 | −1.65% | 0.86 | 0.86 | 0/4 | −1.50% |
| ETH 1日 | −0.25% | 0.60 | 0.86 | 1/4 | −0.13% |
| ETH 3日 | −0.68% | 0.71 | 0.86 | 1/4 | −0.53% |

- 判定: **頑健な追加情報なし**。
- MJ 対 M0（VIX なしで JIV だけ）: −0.18%〜−0.52%。MV 対 M0: −0.30%〜+0.18%（最大は ETH 3日、p = 0.09、q = 0.61）。
- M0 対 拡大平均: OOS R² 0.50（BTC 1日）〜0.54（ETH 1日）、4暦年すべて正。
- ボラティリティ目標の Sharpe（2023–2026）: BTC 一定1倍 1.02、M0 0.92、MV 0.92、MVJ 0.92。
  ETH 0.50、0.44、0.44、0.45。最大ドローダウンは BTC で一定1倍 −53% に対し −60%。
- イベント（19:00 UTC 起点）: 8セルすべてでイベント後の平均が全日平均を下回りました
  （BTC 1日 −0.26%/−0.33%、3日 −0.57%/−1.14%、ETH 3日 −1.33%/−2.17%）。両側 p 0.03〜0.46、BH q ≥ 0.25 で、
  有意ではありません。8セルは独立ではありません（JIV イベント55件中35件は TOPIX イベントと重なり、
  BTC と ETH の3日前方リターンの相関は 0.81）。3日後までの安値もイベント後のほうが深い（BTC −5.2% 対 −3.9%）ものの、
  イベント前7日の実現ボラティリティが高いことでかなり説明できます。

## 実行後の変更と事後分析

いずれも結果を見た後の作業なので、判定の根拠とは分けて記録します。

- **JIV の作り方を変更**: 当初は「30日以下の対象限月がない日は最も近い限月の値をそのまま使う（flat）」でした。
  独立レビューで、flat と補間が切り替わる日に Δlog JIV が人工的に跳ね、JIV イベントが名目5%に対して
  切替日で9.4% 立つことが分かりました。週次限月がなかった頃の VIX と同じ外挿に改め、全体を再実行しました。
  主ファミリーの OOS R² はほぼ同じ（例 BTC 3日 −1.68% → −1.65%）で、判定は変わりません。旧版の出力は手元に残しています。
- **研究境界の徹底**: 当初は日本側の入力を2026-10まで読み、データ検査の集計に含めていました（モデルには未使用）。
  2026-08-01 より前に切るよう修正しました。
- **判断時刻 07:00 UTC の感度**（J-Quants の公開時刻では実現できない仮定）: MVJ 対 MV の OOS R² は
  −0.62%〜−2.87% で、遅い公開時刻が帰無の原因ではありません。この設定では、イベント後1日の平均が全日平均を上回りました
  （BTC +0.83%、ETH +1.02%、TOPIX イベント、両側 p 0.03〜0.05、BH q 0.22）。
- **時間帯分解**（2021-02〜2026-07、TOPIX イベント73日）: 東京時間（00:00–06:30 UTC）に BTC −1.06%、ETH −1.51%、
  欧米時間（07:00–19:00 UTC）に BTC +0.61%、ETH +0.73%、翌日（19:00–19:00 UTC）に BTC −0.27%、ETH −0.36%。
  この形から次の独立期間検証を設計しました。

## 事後仮説の独立期間検証（設計を先に固定）

上の事後分析で、TOPIX 急落日に暗号資産が東京時間に下げ、欧米時間（07:00–19:00 UTC）に一部を戻す形が見えました。
日本時間の投げ売り（追証・キャリー解消）を欧米時間の流動性が吸収する、という利益源泉の説明は付きますが、
**データを見てから作った仮説**です。そこで、本リポジトリで一度も分析していない2021年より前の期間で、
次の条件のまま一度だけ検証しました（`backtests/japan_session_reversal.py`）。

- 期間: 2017-08-17（Binance spot 1分足の開始）〜2020-12-31 の東証営業日。TOPIX の閾値に250営業日以上の
  過去が必要なので（J-Quants の TOPIX は2016-10-03から）、実際のイベントは2017年10月以降です。
- イベント: 主分析と同じ。TOPIX 終値の対数リターン（7暦日以内の直前営業日比）が、その日より前の履歴の5%分位以下。
- 取引窓: d 08:00 UTC（TOPIX の J-Quants 公開目安 16:30 JST の30分後）の1分足始値から、d 19:00 UTC の1分足始値まで。
- 統計: 窓の対数リターンについて、イベント日平均 − 全営業日平均。月クラスター bootstrap（4,000回）の片側 p（差 > 0）。
- **判定**: BTCUSDT spot で片側 p < 0.05、かつイベント日平均から往復14bp を引いても正なら「独立期間で再現」。
  ETHUSDT spot は副次。発見期間（2021-01〜2026-07、`market.db` の spot）の同じ統計は参考として並べ、判定には使いません。
- 期間外の生データは `/mnt/e/Datas/market/holdout_pre2021/` に置き、`load_to_sqlite.py` が読む場所と分けます
  （`market.db` と research manifest の固定を崩さないため）。

イベントは40件前後の見込みで検出力は低く、再現しなかったことは効果がない証明になりません。2020年以前は暗号資産と
株式の連動が弱く、構造が違う可能性もあります。再現しても売買推奨ではなく、封印済み registry とは別の事前登録で
将来検証する候補にとどまります。

補記（統計の算出前）: 初回実行は読込時点で停止しました。Binance spot のアーカイブに、分の格子からずれた時刻の行
（2017-12-04〜18 に約20秒ずれの20,401行、2018-02-09〜10 に約14秒ずれの1,201行。BTC/ETH とも同じ。同期間に正しい時刻の行はない）
があったためです。これらは丸めずに欠測として扱い、件数を出力に記録します。
この規則は結果を見る前に追加しました。該当期間の日は窓の始値か終値が欠けるので、標本から外れます。

### 結果: 再現せず

| 期間 | 資産 | 営業日 | イベント | イベント平均 | 全日平均 | 差 [95% CI] | 片側 p |
|---|---|---:|---:|---:|---:|---|---:|
| 2017-08〜2020-12（検証） | BTC | 803 | 62 | −0.30% | +0.06% | −0.36% [−1.16%, +0.60%] | 0.77 |
| 2017-08〜2020-12（検証） | ETH | 803 | 62 | −0.62% | −0.14% | −0.48% [−1.34%, +0.52%] | 0.83 |

この利益源泉は、少なくとも安定した形では存在しないと判断します。既存の清算リバージョンが年により符号反転したことと整合的です。

## データの取扱い（ライセンス）

J-Quants は個人の私的利用が前提で、生データや元データを復元できる派生物の第三者共有は制限されています。
本リポジトリは公開リポジトリなので、次を機械的に守ります。

- 原本・SQLite・分析結果は既定で `/mnt/e/Datas/market/jquants/` に置き、**リポジトリ内への出力は拒否**します。
- 日次の特徴量（JIV 等）を含む CSV はコミットしません。リポジトリにはコード、合成データのテスト、この文書の集計値だけを置きます。
- APIキーはプロセス環境変数 `JQUANTS_API_KEY`、なければリポジトリ直下 `.env` の `JQUANTS_API_KEY`
  （旧名 `JQUANTS_APIKEY` も可、後の行が優先）から読みます。`.env` は `.gitignore` 対象です。
  キーは `api.jquants.com` への要求だけに付け、リダイレクトを追わず、署名付きダウンロードURLには付けません。
- 解約・ダウングレード時は `/mnt/e/Datas/market/jquants/` 全体（raw、`_superseded`、`jquants.db`、results）を削除対象とします。
  バックアップを作った場合はそれも含めます。

## 実行

```bash
cd /home/o9oem/workspace/crypto/analytics
python3 data-tools/fetch_jquants.py sync            # 外部通信。差分のみ取得
python3 data-tools/fetch_jquants.py build           # 通信なし。raw から jquants.db を再構築
python3 data-tools/fetch_fred_series.py --series VIXCLS
python3 backtests/japan_crossmarket.py              # 通信なし。market.db は read-only
# 独立期間検証（2017-08〜2020-12 の spot 1分足を別の場所へ）
for s in BTCUSDT ETHUSDT; do
  python3 data-tools/fetch_binance_klines.py --market spot --symbol $s --start 2017-08 --end 2020-12 \
    --base /mnt/e/Datas/market/holdout_pre2021
done
python3 backtests/japan_session_reversal.py
```

`sync` は bulk 一覧の更新時刻とサイズが同じで、手元の SHA-256 が台帳と一致するファイルを再取得しません。
内容が変わったファイルは `_superseded/` に旧版を残します。同時実行はロックで拒否します。
`build` は各ファイルを SHA-256 で検証したバイト列から読み、更新時刻が新しいファイルがその中の日付をすべて置き換えます。
オプションの行があるのに ATM が1組も取れないファイルは、仕様変更の疑いとして失敗させます。
FRED の更新は行の追加だけなら自動で反映し、既存行が変わる場合は `--force` が必要です。
両分析スクリプトは入力と出力の SHA-256 を `manifest.json` に残します。

## 解釈上の注意

- 2023年以降の OOS も、設計を書いた後に回した retrospective な評価です。封印された将来検証ではありません。
- 日本固有のショックは少数（代表例は2024年8月）です。月除外の感度も負のままでした。
- JIV は清算値ベースの IV で、日経VI とは算出方法が異なります。流動性の低い限月では理論値に近い清算値が混じります。
- 帰無の結論は、日足・判断時刻1つ・1〜3日の地平線についてです。日中の伝播や、より長い地平線は調べていません。
- bulk ファイルは2026年10月時点の版で、初出時の値と異なる訂正を含む可能性があります。
