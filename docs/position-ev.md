# ポジション期待値分析

`backtests/position_ev.py` は、**事前に固定したポジション案**を過去の全判断時刻で機械的に再生し、
コスト・Funding・損切・利確・清算を含めた純損益の分布と期待値を出す。
これまでのレポートで「反発確率・期待利益・約定後の勝率は未検証」として残していた部分を、
同じ規則で比較できる形にする。

答えられる問い:

- この銘柄・方向・保有時間・損切/利確・レバレッジの組合せは、過去の同じ規則で平均いくら残ったか。
- 指値で押し目を待つことは、成行より期待値を改善したか。約定しなかった判断の機会損失はどれだけか。
- 「7日上昇率が高い」「24時間レンジ上端」などの条件は、無条件のベースラインより良かったか。
- その差は年ごとに安定していたか、月クラスター bootstrap の区間でゼロを除外できるか。

答えないこと: 将来の勝率予測、売買推奨、最適パラメータ。結果は「固定規則を過去に当てた記述統計」であり、
条件やパラメータを結果を見ながら選んだ時点で探索的な数字になる。

## 実行

リポジトリルートから実行する。DB は read-only で開き、出力先は新規または空のディレクトリに限る。
`results/` 配下は research manifest の固定対象なので、一時ディレクトリへ出力する。

```bash
# BTC 成行ロング 24h、損切 300bp / 利確 600bp、7日上昇率 +5% 以上の条件付き
python3 backtests/position_ev.py \
  --venue binance --symbol BTCUSDT --side long \
  --horizon-hours 24 --stop-bp 300 --take-bp 600 \
  --start 2023-01-01 --where 'ret_7d_bp>=500' \
  --output-dir /tmp/position-ev-btc

# HYPE 押し目指値（判断時 open の 50bp 下、6時間有効）、3倍。HL で建てる想定なので
# Funding は HL の実績、手数料も HL の値を明示（価格経路は Bybit perp）
python3 backtests/position_ev.py \
  --venue bybit --symbol HYPEUSDT --side long \
  --horizon-hours 24 --stop-bp 500 --take-bp 1000 \
  --entry-offset-bp 50 --entry-window-hours 6 --leverage 3 \
  --funding-venue hyperliquid --taker-fee-bp 4.5 --maker-fee-bp 1.5 \
  --output-dir /tmp/position-ev-hype
```

価格経路は DB にある市場だけ使える（Binance perp/spot の BTCUSDT・ETHUSDT、Bybit perp/spot の
HYPEUSDT など）。Hyperliquid の klines はないため、HL で建てる想定でも価格経路は Binance/Bybit を
代理に使い、Funding は `--funding-venue hyperliquid` で HL の実績を当てる。手数料の既定値は
`--venue`（価格経路の取引所）のものなので、HL の手数料は `--taker-fee-bp` / `--maker-fee-bp` で明示する。

主な引数:

| 引数 | 既定 | 意味 |
|---|---|---|
| `--horizon-hours` | 必須 | 約定からの最大保有時間。期限到達時は次の足の open で成行決済 |
| `--stop-bp` / `--take-bp` | なし | 約定価格からの損切・利確幅。省略すると期限決済と清算だけ |
| `--entry-offset-bp` / `--entry-window-hours` | 0 / 0 | 0 なら判断足 open で成行。正なら判断足 open から不利でない側へ置く指値と有効時間 |
| `--fill-through-bp` | 1 | 指値を何 bp 突き抜けたら約定とみなすか。タッチだけの約定は仮定しない |
| `--leverage` / `--maintenance-margin-rate` | 1 / 0.005 | 分離マージンの清算価格を計算し、損切より近ければ清算が先に発動 |
| `--taker-fee-bp` / `--maker-fee-bp` / `--slippage-bp` | venue 別 / 2 | Binance 5/2、Bybit 5.5/2、HL 4.5/1.5。スリッページは成行・逆指値・期限決済のみ |
| `--funding-venue` / `--funding-symbol` | 価格と同じ venue | perp の Funding 実績の取得元。`none` で無視（manifest に残る） |
| `--where` | なし | 判断時点の特徴量による条件。複数指定は AND |
| `--start` / `--end` | 最古+30日 / 2026-08-01 | 判断の開始と、決済を含む全足の排他的上限。上限は 2026-08-01 UTC より後にできない |
| `--step-minutes` | 60 | 判断グリッド間隔（UTC 整列） |
| `--notional-usd` | なし | 指定すると1判断あたり期待値を USD 換算 |

## 計算規則

### 判断とエントリー

- 判断時刻は `--step-minutes` 間隔の UTC グリッド。各判断は独立した「その時点で同じ案を実行したら」の仮想取引。
- 判断を採用するかは結果を見ずに決める。指値有効時間と保有時間を足した**最遅の決済足 open** が
  `--end`（既定 2026-08-01 UTC）と DB の最終足より前にある判断だけを使う。
- データ不足の判定も結果より前に行う。判断足から最遅の決済足までの**計画窓全体**に欠損足があるか、
  計画窓の Funding 被覆が不足すれば、その判断は決済の仕方にかかわらず `unknown` とする。
  早く損切された取引だけが「既知」として残り、標本が損失側に偏ることを防ぐ。
- 成行: 判断足 open で約定。taker fee + slippage。
- 指値: 価格は判断足 open × (1 ∓ offset)。有効時間内に low（short は high）が指値を
  `fill-through-bp` 突き抜けた最初の足で、**指値価格ちょうど**で約定（maker fee、スリッページなし）。
  約定前に欠損足があれば `unknown`、最後まで届かなければ `unfilled`。

### 決済と 1 分足の曖昧さ

- 損切は逆指値（成行）。足の open が既に損切を越えていれば open で、足中なら損切価格で決済し、taker + slippage。
- 利確は指値。open で越えていても利確価格で約定（maker）。
- 清算価格は分離マージン近似 `long: E(1−1/L)/(1−mmr)`、`short: E(1+1/L)/(1+mmr)`。
  損切より近いと清算が先に発動し、証拠金全損（名目 −1/L）とエントリーコストを損失とする。
  損切の方が近くても、足の open が清算価格まで一気に越えた場合は清算として扱い、証拠金を超える損失は計上しない。
- どれにも当たらなければ `entry + horizon` 足の open で期限決済。期限足の high/low/close は使わない。
- 1 分足では高値と安値の順序が分からない。同じ足で損切と利確の両方に触れた場合や、
  **指値約定足の高値**（約定前だった可能性がある）だけが利確に届いた場合は、
  悲観（不利側が先）と楽観（有利側が先）の両方を計算し `ambiguous=true` とする。
  悲観値を主指標とし、楽観値は上限の参考として並べる。
  指値約定足の安値は約定後と確定できる（価格は指値を通過してから安値に達する）ので、損切は確定扱い。

### Funding

- perp は `--funding-venue` の決済実績を使う。保有区間は `[約定, 決済)` の半開区間で、
  決済時刻はミリ秒の実時刻のまま比較する。成行は判断足 open から、指値は約定足の終わりから数える。
  足中の決済は足の終わりまで保有したとみなす。
- 1 回の支払いは `rate × 決済分の open / 約定価格` で、ロングは正の rate で支払い、ショートは受け取る。
  決済分の open は価格経路 venue の値で、mark price の近似。
- 被覆は計画窓（判断足 open から最遅の決済足 open まで）で判断ごとに一度だけ確認する。窓の前に決済実績があり、
  窓内に間隔の 1.5 倍を超える空白がないことを求める。`--end` 以後の行は読み込まない。
  最後に読み込んだ決済から 1 間隔以内に窓が閉じる場合は、次の決済がまだ来ないので被覆ありとする。
  それ以外は `unknown` とし、ゼロで埋めない。決済間隔が途中で変わる場合、この末尾規則は成り立たない。

### 特徴量と条件（すべて判断足より前に完成した足のみ）

| 特徴量 | 定義 |
|---|---|
| `ret_4h_bp` / `ret_24h_bp` / `ret_7d_bp` | 直前足 close の 4 時間・24 時間・7 日前比 |
| `rv_24h_bp` | 直近 24 時間の 60 分対数リターン二乗平均から求めた日次換算ボラティリティ |
| `rv_ratio_24h_30d` | 24 時間ボラ ÷ 30 日ボラ。1 未満は相対的な低ボラ |
| `range_pos_24h` | 直近 24 時間の高安レンジ内での直前 close の位置（0=安値、1=高値） |
| `funding_8h_bp` | 判断時刻までに**決済済み**の最新 Funding を 8 時間換算（1.5 間隔以上古ければ欠測） |

リターン系は両端の足だけ、ボラティリティとレンジ系は窓内の全足を使い、使う足に欠損があれば欠測とする。
Binance spot のように欠損分がある市場では、1 分の欠損で 30 日ボラを使う `rv_ratio_24h_30d` が 30 日間欠測になる。
条件で使う特徴量が欠測の判断は、ベースラインからも条件付きからも外し、
同じ母集団で比較する。`position_feature_quantiles.csv` にベースラインの分位点を出すので、
現在値が過去分布のどこにあるかを確認してから帯を決める。

### 統計

- **1 判断あたり期待値**（`ev_per_decision_*`）が主指標。指値の未約定は 0、`unknown` は除外。
  成行では 1 取引あたりと一致する。
- 区間は判断の UTC 月を cluster とする bootstrap（既定 2,000 回）の 95% 区間。
  時間グリッドの判断は保有期間が重なるため、取引数をそのまま独立標本数とみなさない。
- `conditional_minus_baseline` は同じ月の再標本で条件付きとベースラインの差を取る。
  再標本に条件該当月が1つもない回数は `bootstrap_draws_without_condition` に残す。
- `ev_status`: 取引 30 件未満または稼働月 6 未満は `insufficient_sample`。
  それ以外は区間の位置で `ci_above_zero` / `ci_below_zero` / `ci_includes_zero`。合否判定や推奨ではない。
- 重複を除いた参考値として、悲観決済時刻で前の取引と重ならない取引だけを時系列順に残した
  `nonoverlap_trades` / `nonoverlap_ev_pess_bp` を併記する。
- 指値案では同じ判断を成行で実行した参照値も出す。`market_ev_when_filled_bp` と
  `market_ev_when_unfilled_bp` の差は、指値が約定するときほど価格が不利に動いていた度合い（逆選択）と、
  未約定で逃した値動きの大きさを示す。

## 出力

- `position_ledger.csv`: 判断ごとの特徴量、条件該当、状態（`complete` / `unfilled` / `unknown` と理由）、
  約定、悲観・楽観の決済種別・時刻・粗損益・コスト・Funding・純損益・証拠金比損益。
  `path_mae_bp` / `path_mfe_bp` は損切・利確で早く決済した後も含む**計画保有時間全体**の逆行・順行で、
  損切幅の妥当性を見るための値（指値約定足の高値は順行に含めない）。
- `position_summary.csv`: ベースライン・条件付き・差分。期待値と区間、勝率、平均利益/損失、損益分岐勝率、
  profit factor、5% 分位と CVaR、損切/利確/期限/清算率、コスト・Funding 平均、証拠金比の平均と 5% 分位。
- `position_by_year.csv`: 年別の期待値と決済内訳。符号が年で入れ替わるかを確認する。
- `position_feature_quantiles.csv`: 特徴量の分位点。
- `position_manifest.json`: 案の全パラメータ、条件、script・出力の SHA-256、DB のサイズ・更新時刻、
  データ範囲。実行中に DB が変わった場合は結果を書かずに失敗する。

## 実データでの確認例（2026-10-06 実行）

以下は動作確認のための例で、パラメータや条件を探索・選定したものではない。
どれも 95% 区間がゼロを含み、優位性の証拠にはならない。

| 案 | 判断数 | 1判断あたり期待値（悲観） | 95%区間 |
|---|---:|---:|---:|
| BTC 成行ロング 24h・損切300/利確600bp、2023-01〜 | 31,368 | −8.5bp | −20.3〜+3.3 |
| 同、`ret_7d_bp>=500` の条件付き | 6,568 | −2.2bp | −32.3〜+23.2 |
| 条件付き − ベースライン | — | +6.3bp | −16.1〜+24.8 |

年別では、この条件付きは 2023 年 +29bp・2024 年 +8bp に対し 2025 年 −35bp・2026 年 −64bp と符号が反転した。
全期間平均だけでは見えないレジーム依存を、年別表が示す例である。

| 指値案（判断足 open の 50bp 下、6時間有効） | 約定率 | 指値の1判断期待値 | 成行の1判断期待値 | 成行・約定した判断 | 成行・未約定の判断 |
|---|---:|---:|---:|---:|---:|
| HYPE 24h・損切500/利確1000bp・3倍・HL Funding と HL 手数料、2025-01〜 | 83% | −3.1bp | −10.4bp | −61.0bp | +244.5bp |
| BTC 48h・損切300/利確600bp・3倍、2024-01〜 | 56% | −6.8bp | −10.5bp | −66.6bp | +60.4bp |

指値の 1 判断期待値の 95% 区間は HYPE −27.1〜+22.2bp、BTC −20.4〜+7.3bp。

両銘柄とも、指値が約定した判断では成行でも大きく負け、約定しなかった判断では成行が大きく勝っていた。
指値は取得価格とコストを改善するが、約定は下落が続く局面に偏る。指値の価値は両者の差し引きで評価する必要がある。

## 限界

- 1 分足の OHLC だけを使う。板の深さ、約定順位、部分約定、サイズによる impact は含まない
  （サイズ感度は `execution_sensitivity.py` を参照）。`fill-through-bp` は順位の不確実性に対する粗い保守化。
- 清算は分離マージンの単純式。クロスマージン、段階的な維持証拠金、清算手数料、ADL は扱わない。
- Funding の mark は価格経路 venue の 1 分 open で近似する。HL で建てる場合も価格は Binance/Bybit の代理。
- 判断が重なるため、取引数ほどの独立情報はない。月 cluster bootstrap も月をまたぐ重なりや
  レジームの持続までは補正しない。
- 条件や損切幅を結果を見ながら変えると多重比較になる。良い組合せを見つけた場合は、
  案を固定してから将来データで確認する。封印済みの `prospective_validation` とは別物で、その判定にも混ぜない。
- 2026-08-01 以後のデータは使わない。現在の相場状態は DB にないため、`--where` の帯は利用者が
  直近の観測値から指定する。

## 今後の拡張候補

1. **ポジション記録と事後較正**: 実際に建てた案（エントリー時点の計画と特徴量）を記録し、
   本ツールの過去期待値と実現損益を前向きに突き合わせる。過去分布が実取引をどれだけ説明するかを測る。
2. **現在状態の自動取得**: `live_signals` の取得側が受信時刻つきの足を保存できるようになった段階で、
   判断時点の特徴量を同じ定義で計算し、近傍の過去状態（分位帯）を自動で条件にする。
3. **損切・利確・保有時間の感度面**: 複数案を一度に評価する場合は、学習期間で選び検証期間で確認する
   分割と多重比較補正を組み込んだ上で行う。単純なグリッド最大値は報告しない。
4. **OI・taker flow 特徴量**: `taker_flow.py` の因果的な OI・フロー指標を条件に追加する。
   OI の公開時刻と古さを判断時刻に合わせる必要がある。
5. **複数ポジションの合算**: BTC・HYPE の同時保有など相関したポジションを、同じ判断時刻で合算した
   口座単位の損益分布として評価する。
